## 执行前端重构 M0（数据打通）+ M3（系统子模块补齐）

### 关键架构事实（前端 frontend/ 对接后端 backend/）
- **URL 约定**：所有 API 走 `baseURL=/admin/api`，路径形如 `/workspace/{ws_id}/<resource>/<sub>`。
  `PathRewriteMiddleware`（`backend/app/middleware/path_rewrite.py`）会把 `/workspace/{ws}/` 段剥离、并把 `APPLICATION/TOOL/...` 转小写，最终命中后端 router 真实前缀 `/api/<resource>`。
  所以前端 API 模块一律用 `/workspace/${wsId}/<resource>` 前缀（参考 `lib/api/knowledge/knowledge.ts`）。
- **响应信封**：经 `/admin/api` 进来的请求被 `LegacyResponseMiddleware` 包成 `{code, data, message}`；`lib/request` 的 `promise()` 解包为 `response.data`（即信封），页面用 `res.data` 取 payload。
- **wsId 取用**：`useUserStore.getState().getWorkspaceId()`（store 在 `frontend/src/store/`）。

## 老 ui（Vue）连接新 FastAPI 后端（端口 8081）

目标组合：**老 `ui/` 前端 → 新 `backend/` FastAPI 后端（端口 8081）**。端口 8080 仍为老 Django 后端，二者并存。

### 配置要点
- FastAPI `backend/main.py` 端口本就是 8081（`port=8081`），无需改端口。
- 老 ui 请求前缀 `/admin/api`、`/chat/api` 由 `PathRewriteMiddleware` 重写到 `/api`。**必须**在 `backend/.env` 设置 `MAXKB_API_PREFIX=/admin/api`、`MAXKB_CHAT_API_PREFIX=/chat/api`，否则中间件跳过重写、老 ui 全部 404。`backend/.env` 已加上这两行。
- 老 ui 的 `ui/vite.config.ts` 代理目标统一为 `http://127.0.0.1:8081`（先前误改为 8080，已改回）。改完需重启 `npm run dev` 才生效。

### 修复的阻断性后端缺陷（否则老 ui 首屏 500）
1. **缺 `greenlet`**：异步 SQLAlchemy 必需，`No module named 'greenlet'`。已 `pip install greenlet>=3.0` 到运行环境（miniforge py311），并加入 `backend/pyproject.toml` 依赖。
2. **缺 `pycryptodome`**：`rsa_util.py` 用 `Crypto`，`No module named 'Crypto'`。已安装 `pycryptodome>=3.20` 并加入 `pyproject.toml`。
3. **`system_setting.create_time` NOT NULL 冲突**：`rsa_util.get_or_create_key_pair` 创建 `SystemSetting` 时未填 `create_time`/`update_time`（`AppTableBase` 默认 None，但 Django 表该列 NOT NULL），插入报 IntegrityError。已在 `rsa_util.py` 创建时填 `datetime.now()`。

### 验证
- `8081 /admin/api/profile`（带 token）→ 200；`/admin/api/user/login` admin→200、错密→401；`/admin/api/user/list`→200。
- `8080 /admin/api/profile`→200（老 Django 仍正常）。
- 运行环境：后端实际由 `miniforge3/envs/py311/bin/python` 启动（`python main.py`，cwd=backend/），非 uv `.venv`。`backend/.venv` 也缺 greenlet/pycryptodome。

## 新前端（Next.js）登录 401 修复

**现象**：`POST /admin/api/user/login` → 401。后端登录逻辑本身 OK（老 ui 在 8081 验证过 admin→200）。

**根因**：RSA 公钥端点错位。
- 后端在 **`GET /api/system/profile`**（公开、无需登录，`system.py:44` 返回 `rsa`）提供公钥；`rsa_util.get_or_create_key_pair` 落库 `system_setting(type=3)`。
- 新前端 `store/user.ts` 的 `fetchRsa()` 却调 **`/user/profile`**（`auth.py:84` `profile_alias`），该端点**要求已登录 token**（`Depends(get_current_user)`）且**不返回 `rsa`** → 公钥永远拿不到，登录链路断。

**修复**：`frontend/src/store/user.ts` 的 `fetchRsa` 改为 `get('/system/profile')` 取 `data.rsa`（并 import `get` from `@/lib/request`）。登录页仍依赖 `rsaKey` 非空才 POST，逻辑不变。lint 0 错误。

**注意**：`/system/profile` 经 next.config rewrites（`/admin/api/*`→`target/admin/api/*`）再经后端 `PathRewriteMiddleware`（`/admin/api`→`/api`）命中，需 `API_TARGET` 指向 8081 且后端 `MAXKB_API_PREFIX=/admin/api`。
