## 后端一致性对比（backend/ FastAPI vs apps/ Django）
- 用户要求检查重构后端是否与原 Django 后端功能一致；确认范围=全面对比(API+数据模型+行为算法)、静态代码对比(不起服务)、产出对比文档+差距清单。
- 交付物：`backend/docs/CONSISTENCY_REPORT.md`。
- 关键发现：
  - 数据模型 44 张表名对齐，但 `knowledge_action` 表完全缺失、`application_version` 缺 `workspace_id`/`application_name` 字段（P0）。
  - API 顶层模块全覆盖，但约 40+ 二级端点缺失（application 导入导出/分页/improve、chat 的 embed/mcp/share/clear 等）。
  - 工作流 36/36 节点类型对齐，但部分节点为占位/透传，且缺 Django 的 workflow_mode 维度。
  - 行为算法：切分断句算法有偏差、检索缺 keywords 模式、向量化缺 Termbase 词典注入、Agent 记忆策略不同、Provider 仅映射未写厂商专用实现。
- 总体判断：重构后端处"可运行骨架+核心链路原型"阶段，距功能一致可上线仍有 P0/P1 缺口，且真实 PG/Redis 端到端验证未完成。

## 新增 apps 原后端启停脚本
- 新增 `apps/scripts/start.sh` 与 `apps/scripts/stop.sh`，对应 `backend/scripts/` 模板，管理原 Django 后端的 `web`(dev web) 与 `celery`(dev celery) 两个服务（默认 all）。
- 设计：Python 解析优先级 `uv run python`→`.venv/bin/python`→`python`；把 `.venv/bin` 加入 PATH 以让 `dev celery` 子进程能找到裸 `celery` CLI；用 `setsid` 启动使每个服务成为进程组组长，`stop.sh` 用 `kill -TERM -- -<pid>` 按进程组整体终止（含 celery 子进程）。pidfile=run/<name>.pid，日志=run/<name>.log。
- ROOT 解析：`apps/scripts` 的 `../..` = 仓库根（main.py 与 .venv 所在）。
