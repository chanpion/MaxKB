## apps(Django) 配置加载机制（config.yaml vs 根目录 .env vs ui/env/.env）
- `apps/maxkb/const.py` 启动时 `load_dotenv()` 加载**仓库根目录 `.env`** 到 os.environ。
- 根目录 `.env` 的 `MAXKB_CONFIG=1` 决定配置 root_path 用仓库根（否则去 `<root>/conf/` 找，本地会报错）。
- 配置有两种模式（`conf.py`，由 `MAXKB_CONFIG_TYPE` 决定）：默认 FILE 模式读 `config.yaml`；设 `MAXKB_CONFIG_TYPE=ENV` 时读 `.env` 里 `MAXKB_*` 前缀变量（剥前缀）。二选一，另一方被忽略。
- 默认(FILE)下 `.env` 里 `MAXKB_DB_*`/`MAXKB_REDIS_*` 被忽略，只有 `MAXKB_CONFIG=1` 生效；真正连接配置来自 `config.yaml`。
- 当前两文件连接信息不一致：config.yaml=10.58.12.60(远程)，.env=127.0.0.1(本地)。默认走 config.yaml。
- `ui/env/.env` 是前端 Vite 配置（VITE_ 前缀），与后端两者完全无关。

## 本地启动 apps 后端实操（macOS/v3, 2026-07-12, PG=127.0.0.1:5432 pg/pgvector123, Redis=127.0.0.1:6379/123456）
- uv 不在 PATH：用系统 pip3+清华镜像装 uv 到 `~/Library/Python/3.9/bin/uv`。
- `.venv` 原是 conda py311 符号链接且无依赖：`mv .venv .venv.conda` 后 `uv venv --python miniforge3/envs/py311/bin/python3.11` + `uv sync --index-url https://pypi.tuna.tsinghua.edu.cn/simple`。
- DB：手动 `CREATE DATABASE maxkb` 并在库内 `CREATE EXTENSION vector`(pgvector)。
- config.yaml 需补 `EMBEDDING_MODEL_PATH`/`EMBEDDING_MODEL_NAME`(否则迁移 0001 的 model_name=null 报 IntegrityError；官方默认 shibing624_text2vec-base-chinese)。
- pyproject 缺 jinja2(wsgi 用到)：`uv pip install jinja2`(建议补进 pyproject)。
- 3 处 v3 分支在新依赖下必需的代码修复：① sandbox_shell.py:68-70 字符串间缺 `+`(SyntaxError)；② settings/lib.py:24 CELERY_BROKER_URL_FORMAT 去 `?protocol=2`(新版 kombu/redis-py 不接受)；③ conf.py get_cache_setting 去 cache 的 protocol:2。
- 启动：`nohup .venv/bin/python main.py dev web &` 与 `PATH=.venv/bin:$PATH nohup .venv/bin/python main.py dev celery &`；web 监听 8080，celery 显示 ready。注意 dev 模式命令会阻塞，需用 nohup/后台方式。
